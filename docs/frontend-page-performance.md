# Smart Data Agent 页面性能优化方案

## 目标与边界

本方案覆盖菜单切换、页面首屏、列表/目录读取和可视化报表回读。优化必须保持租户、用户、权限和数据新鲜度边界；浏览器不得长期缓存 HTML 或租户业务 API。静态版本化资源继续使用 immutable，HTML 与业务 API 继续使用 no-store。

当前验收预算：

- 已预取或短缓存命中的菜单到可用页面目标不超过 600ms，不出现整页空白等待。
- 冷启动先在 300ms 内显示页面框架或明确的局部加载态，慢目录不得阻塞标题、按钮和已保存配置。
- 同一租户、同一用户、同一路径的并发 GET 只发出一次；写操作成功后旧读取缓存立即失效。
- 已保存可视化图表在数据投影完成前显示“正在读取报表数据”，不得误显示“暂无可视化数据”。

## 已落地架构

| 层级 | 机制 | 范围 | 新鲜度/失效 |
|---|---|---|---|
| 路由代码 | 悬停、键盘聚焦即时预加载；空闲时逐个预热可见路由 | 所有菜单页面 | 当前构建版本 |
| 路由数据 | 只预取用户当前指向页面的权威依赖 | 可视化报表、我的报表、智能分析、数据资产、系统配置和主要应用页 | 复用服务层短缓存 |
| 客户端读取 | 内存短缓存、并发请求合并、返回值深拷贝 | 数据资产、应用模块、我的分析、指标、导航、租户、主题/页面数据 | 8–60 秒；任一成功写操作全部失效 |
| 页面渲染 | 页面框架与大目录渐进加载，标准图表延迟到数据投影完成后挂载 | 可视化报表与我的报表 | 当前请求完成即更新 |
| 服务端 | CSV 目录/快照复用既有有界缓存 | 数据资产目录 | 沿用服务端 60 秒缓存和租户隔离 |
| HTTP | 版本化静态资源 immutable；HTML、权限和租户 API no-store | 全站 | 不改变现有安全策略 |

客户端缓存键包含完整路径、实际请求头、tenantId 和 userId；认证接口不进入缓存。401 刷新重试绕开缓存，防止请求自等待。机构切换和所有成功 POST/PUT/PATCH/DELETE 都会清空缓存，优先保证权限与配置一致性。

## 页面依赖矩阵

| 页面 | 首要数据 | 当前策略 |
|---|---|---|
| 多机构分析、经营周报、机构督导、客户洞察、竞争分析 | 对应 application module | 悬停预取，8 秒短缓存，请求合并 |
| 智能分析 | 数据资产目录、运行时主题、指标、已保存分析 | 悬停预取；完整目录 20 秒、指标 30 秒、结果 10 秒 |
| 分析配置 | 数据资产目录、知识投影 | 悬停/聚焦/按下即并行预取两项；同请求合并；冷进入显示表格骨架，不闪现假空态 |
| Skill 插件 | 知识投影 | 只预取知识投影，不读取无关 CSV 目录 |
| 可视化报表 | 报表配置、原始表目录、运行时主题 | 配置先渲染；瘦目录缓存 60 秒（与现有服务端目录缓存一致）；相同请求合并 |
| 我的报表 | 智能分析结果、可视化报表配置、图表数据目录 | 悬停只预取两类首屏列表；展开图表时只读取一次瘦目录；回读期间显示真实加载态 |
| 数据资产 | 完整资产目录、指标字典 | 悬停预取；20/30 秒短缓存；工具调用子页只读取目录，不预取无关指标字典 |
| 自动化任务 | 任务定义、能力目录、资产、指标、模型配置 | 悬停精确预取；任务/能力 8 秒短缓存；待办页不再读取这些专属依赖 |
| 待办、推送 | 对应 application module | 悬停预取，8 秒短缓存 |
| 系统管理 | 配置、用户/角色、审计各自的首屏数据 | 按子页独立预取与挂载；配置沿用 5 秒缓存，用户/角色 8 秒，审计 5 秒；不再每页全量读取 |

空闲代码预热会先处理当前菜单分组：自助分析、经营分析、任务工作台、数据资产、推送订阅、系统管理的相邻页面均早于无关页面；组内仍逐个调度，不并发抢占当前页面主线程。菜单按下事件作为鼠标快速点击和触屏操作的兜底，悬停与键盘聚焦行为保持不变。

## 后续分阶段优化

1. 观测：统一记录 route-ready、API TTFB、响应体积、缓存命中和长任务；按页面建立 P50/P95 基线。
2. 接口瘦身：把 `/api/data-assets` 的 150KB 级完整包拆成目录摘要、按页详情和按需预览；可视化只读取所引用数据集。
3. 服务端读模型：为导航、指标摘要、应用模块和报表列表增加按租户版本号的投影缓存；写入后以版本或事件精确失效。
4. 渲染预算：长列表虚拟化，重图表进入视口再挂载，非关键面板保持局部 Suspense/骨架屏。
5. 持续门禁：在浏览器回归中记录冷/热两轮请求数和可用时间，超过预算或出现重复大请求即失败。

## 验证与回滚

运行 `npm run typecheck`、`npm run test:route-performance`、`npm run test:visual-report-workbench`、后端可视化报表单测，并在真实浏览器验证冷/热导航、图表加载态和弹窗底栏边界。

2026-08-17 本地认证路由复测（1512×982，5174/8788）：分析配置冷启动页面框架由约 472ms 降到 228ms，数据完成约 1.02s；页面稳定后悬停 500ms 再点击，分析配置 68ms 可用。指标字典、经营周报、自动化任务、系统配置的热切换页面框架为 61–78ms，约 0.37–0.39s 内稳定。自动化任务在精确预取后 56ms 读取到服务端任务状态。冷打开系统配置不再请求用户/角色；冷打开待办只请求 `agent_workspace`，不再请求自动化任务、能力、资产或指标。未登录访问分析配置仍跳转登录且不请求数据资产。

构建后的重页面代码块仍依次集中在数据资产（114.09KB）、智能分析（99.32KB）、周报（83.93KB）、任务工作台（72.34KB）和系统配置（70.54KB，均为构建表原始大小）；当前菜单分组优先预热用于吸收这些代码块的交互等待。组件行数门禁仍因既有 `WeeklyReport.tsx` 3068 行、`SelfAnalysis.tsx` 3057 行超过 3000 行而失败，本轮未修改这两个文件，后续拆分必须另立范围并保持功能契约。

回滚时可独立撤销 `routeDataPreload.ts` 与 Layout 的数据预取；移除各 GET 的 `readCache` 即恢复直读；可视化加载态、稳定 sourceKey 回绑和弹窗布局可分别回滚，不涉及生产数据迁移。

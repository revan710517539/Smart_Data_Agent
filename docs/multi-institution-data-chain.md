# 多机构数据应用链设计

## 目标与边界

系统只允许“数据资产 → 数据管理 → 表关系”访问当前账号权限范围内的跨机构数据目录。表关系按参与机构数由服务端自动标记：一个机构为 `single_institution`，两个及以上机构为 `multi_institution`。只有跨机构表关系可以发布为“多机构页面”数据。

多机构页面数据是分析层唯一的跨机构入口。多机构分析、智能分析和可视化报表可以选择它；“我的报表”不重新访问跨机构原始目录，只回读智能分析或可视化报表已保存的受治理资产。

```text
授权机构原始表 / 静态工作簿 Sheet
              ↓
表关系（服务端自动标记单机构/跨机构）
              ↓ 仅跨机构关系
多机构页面（发布、字段选择、关系与模式指纹）
              ↓
多机构分析 / 智能分析 / 可视化报表
              ↓
我的报表（保存结果或受治理引用）
```

## 权威与数据契约

| 层级 | 权威来源 | 必须保留的身份 | 失败关闭条件 |
|---|---|---|---|
| 原始表 | `raw_tables` 统一目录 | tenant、table、schema fingerprint | 无权限、文件/模式不可读 |
| 表关系 | `table_relationships` | relation id、参与机构、节点、主键边 | 机构越权、主键/类型不兼容、关系断开 |
| 多机构页面 | `page_data` | page data id、relation id、schema fingerprint、institution sources | 非跨机构关系、关系失效、模式变化、字段缺失 |
| 分析/报表 | 受治理页面数据读取接口 | 上述身份 + `__institution_name` | 尝试直接浏览跨机构原始目录或读取单机构页面 |
| 我的报表 | 已保存分析快照或可视化引用 | 来源类型、page data id、relation id、schema fingerprint | 来源撤销、关系/模式漂移 |

机构名称由表关系节点向后传递，并在输出中使用 `__institution_name`，可作为图表维度或坐标轴。保存可视化报表时不持久化跨机构数据行，只保存受治理引用；再次打开“我的报表”时重新校验权限、发布状态、关系 ID 和模式指纹。智能分析保存的是当次已授权执行的结果及来源快照，避免后续从报告页面越权重查原始目录。

## 静态工作簿

原始表页支持上传 `.xlsx`，也支持先将飞书表格导出为 `.xlsx` 后上传。每个非空 Sheet 原子生成一张不可变静态原始表；相同内容幂等复用。解析限制文件大小、压缩后展开大小、Sheet 数、行列数及 ZIP 路径，原工作簿和生成的 CSV 均保存在当前租户对象存储中，不写回 Data Crawler 的 `/app/data`。

静态表与 Data Crawler 原始表合并到同一只读目录，因此可被智能分析、可视化报表、主题表处理和表关系使用。直接填写飞书 URL 不在本次上传契约内，避免在缺少飞书身份和文档授权时建立旁路。

## 缓存与性能

目录和页面元数据可以使用租户、用户、权限版本及资产版本组成的短期缓存键；页面数据行和跨机构业务 API 不使用跨用户共享缓存。资产发布、关系变更、权限变化或模式指纹变化必须使对应缓存失效。HTML、登录态和业务 API 保持 `no-store`，版本化静态资源可以长期不可变缓存。

## 验收与回滚

验收覆盖：单/跨机构自动标记、多机构页面只显示跨机构候选、三类分析消费者读取、单机构页面拒绝分析、可视化保存不复制行、我的报表回读、关系/模式变化失败关闭、工作簿多 Sheet 与重复上传、越权负例，以及真实 5174/8788 路由。

该实现不包含数据库迁移或生产部署。回滚仅撤销统一原始表源、工作簿解析与上传、页面数据消费者、可视化绑定和对应 UI/测试；Data Crawler 源文件与既有业务数据保持不变。已上传静态工作簿是内容寻址对象，清理时必须按精确资产 ID 操作，不能递归删除租户目录。

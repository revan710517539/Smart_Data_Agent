# 模型接入到分析表达的生产运行时契约

本文只描述当前 Smart Data Agent 的模型、场景、Skill、Memory 和分析结果链路；
不改变已有页面交互与业务口径。

## 一条完整链路

```text
模型接入弹窗
  → 账号级安全保存（API Key 加密、读取掩码）
  → 连接测试（发现 provider 实际子模型）
  → 管理员启用至少一个子模型
  → 各页面按应用模块展示同一账号可用模型
  → 后端按账号、模块、接入 ID、子模型再次校验
  → 场景识别 Skill 先判断入口、动作、数据范围和分析类型
  → 装载显式 Skill + 场景 Skill + 描述/归因/预测 Skill + 已审核 Memory
  → 模型第一阶段形成受约束分析计划
  → 权限和指标口径下执行真实查询、受控 Python 与证据检查
  → 模型第二阶段只基于实际证据组织业务结论
  → 页面显示数据、图表、结论、降级提示、任务/模型审计
```

模型不能决定租户、权限、SQL 是否可执行、Skill 是否获批或 Memory 是否生效；
这些边界由确定性运行时校验。

## 模型接入状态机

| 阶段 | 状态 | 能否在业务页选择 | 进入下一阶段的条件 |
|---|---|---:|---|
| 新增/修改 | `draft + untested` | 否 | 保存 API 地址与密钥 |
| 连接失败 | `draft + failed` | 否 | 修正后重新测试 |
| 瞬时失败且已有成功版本 | 保留 last-known-good | 是 | 保留上次成功目录并提示本次失败 |
| 测试成功 | `available + connected/mock` | 仍取决于子模型 | provider 返回实际模型目录 |
| 子模型启用 | `enabledModels` 非空 | 是 | 管理员至少勾选一个实际子模型 |
| 全部子模型停用/接入删除 | 无运行时候选 | 否 | 重新启用或接入 |

保存接口强制使用账号级 `global_text_model`，因此同一登录账号切换机构时不会复制或
泄漏模型配置。全局文本模型可以服务所有非语音应用模块；语音接入使用独立类型和
凭据。前端保存的选择只是偏好，后端始终从账号权威配置重新解析，不接受页面提交的
API 地址或密钥。

## 页面与应用模块

| 页面/触发点 | 应用模块 | 模型选择方式 | 场景上下文 |
|---|---|---|---|
| 智能分析主查询、重新分析 | `intelligent_analysis_reasoning` | 用户可选已启用子模型 | 已选表、问题、路由、Skill |
| 图表追问/整页 AI 分析栏 | `intelligent_analysis_reasoning` | 账号已保存选择或首个可用模型 | 单图或整页数据范围 |
| 周报上下文分析 | `intelligent_analysis_reasoning` | 首个可用模型/已保存选择 | 周报页与绑定指标 |
| 周报结论重新生成 | `weekly_report_conclusion_regeneration` | 应用模块路由 | 已发布版本和证据 |
| 自动分析/指标监控 | `automatic_analysis` | 任务保存接入 ID 与子模型 | 任务配置、指标、触发证据 |
| Memory 提取 | `memory_extraction` | 应用模块路由 | 脱敏后的受治理输入 |
| Skill 自学习与演化 | `skill_evolution_learning` | 应用模块路由 | 候选生成，不自动激活 |

每个入口只显示同时满足以下条件的模型：账号可见、`available`、连接状态为
`connected/mock`、应用模块匹配、`enabledModels` 非空。后台任务同样执行这套校验，
不会因没有页面选择器而绕过。

## 场景识别与意图理解

`scene-analysis-intent` 是所有分析入口的首个规划 Skill。确定性 Router 使用“用户
问题 + 页面上下文”输出四组结构化结果：

1. `surface`：图表追问、整页分析栏、智能分析、文本框语音、图表语音；
2. `action`：分析、记录文本或变换图表；
3. `dataset_scope`：当前图表、当前卡片、已选数据表或整页；
4. `analysis_kinds`：描述性、归因、预测，可组合。

文本框语音会先区分“记录”与“分析”；记录不进入数据分析链。归因必须有对比基线、
贡献与证据边界，不能把相关写成因果。预测必须给区间、假设和失效条件；数据不足时
拒绝伪精确点预测。未出现明确分析词时默认描述性分析。

## 新增 Skill 是否需要改场景代码

通常不需要。新增“某个业务主题/机构方法”的 Skill 时，只要按现有资产契约登记并
通过审批，运行时会从当前租户/账号可见目录动态读取，通过以下信息匹配：Skill ID、
名称、描述、分析方法、机构范围、基础方法类型和 Memory 引用。显式选择的 Skill
优先，场景规划器可再组合最多若干个匹配 Skill。

只有以下情况需要修改稳定 Router 并发版：

- 新增一种页面入口或数据范围，而不是新增业务能力；
- 新增“描述/归因/预测”之外的分析类型；
- 新增记录、分析、图表变换之外的动作；
- 页面没有把识别所需上下文字段传给后端。

因此，机构贷款分析 Skill、产品分析 Skill、渠道分析 Skill 等应走“目录新增 → 审批
→ 动态装载”，不应在 `scene.py` 增加机构名称分支。

## Skill 与 Memory 装载顺序

运行时优先级是：用户显式选择 → 当前账号个人能力 → 当前机构已审核能力 → 平台基础
Skill。场景规划结果会记录在任务快照中；显式已解析 Skill 不会被规划器静默替换。
Memory 只召回 `active` 记录，候选、待审、已拒绝内容不能作为事实进入模型上下文。

生产能力准备 job 会为 11 家机构准备：

- 7 条平台基础场景/方法 Skill：`active`；
- 33 条机构描述/归因/预测覆盖 Skill：`review`；
- 110 条机构与共性方法 Memory：`candidate`。

后两类必须四眼审批后才能进入运行时。API/Worker 启动只验证能力包完整性，不并发
补写或自动激活。

## 模型如何理解 Skill

模型收到的不是一个 Skill 名称列表。运行时会将已授权 Skill 解析为有界上下文，包含
名称、用途、分析方法、输出格式、业务视角、推荐关系、引用 Memory 和证据边界；同时
加入场景判断、分析类型纪律、指标口径、数据源快照和用户问题。第一阶段模型只能生成
结构化分析计划。模型给出的 SQL/Python 仍要经过只读 SQL、指标权限、租户参数、沙箱
和结果 schema 校验；失败时显式记录 `planning_source` 与降级原因。

## 结果表达与失败语义

第二阶段只看到已经执行的查询结果和证据快照，输出固定包含：核心结论、数据证据、
原因边界、经营建议、风险提示、后续动作。表达使用贷款经营语言，避免把算法名、统计
术语或内部实现当成业务结论。

失败时保持“数据与模型结论”分离：

- 第一阶段模型失败：使用受治理默认计划继续，并在页面显示规划降级；
- 查询无数据：不调用慢模型编造结论，返回无数据原因；
- 第二阶段模型失败：保留真实数据和图表，使用证据型确定性结论并显示提示；
- 模型/子模型失效：该候选从选择器和后台路由消失；
- Skill 未获批或无权限：不装载、不执行；
- Crawler manifest/租户映射/checksum 失败：该租户原始表为空并返回明确合同错误。

所有模型调用只审计接入 ID、实际子模型、状态、耗时、请求/响应 hash、任务与 trace
关联；不记录 prompt 正文、API Key 或原始敏感数据。

## 生产验收

上线候选必须同时通过：发布门禁、MySQL 8.0.18 集成、Crawler 只读 manifest、
外部 Worker 心跳、对象存储真实 health、严格 OIDC 浏览器登录/refresh/切机构，以及
一次“模型测试成功 → 启用子模型 → 页面选择 → 描述/归因/预测组合 → Skill 调度 →
证据型表达”的代表性业务验证。HTTP 200 或页面出现模型名称均不能单独视为链路通过。
